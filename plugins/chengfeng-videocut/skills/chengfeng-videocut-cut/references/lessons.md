# 剪口播的事故簿

正文只留规矩，规矩的来历在这里。每条都是真发生过的。

## 转录会把专名听错成什么样（2026-07-28 实测）

一份 39 个含字母词的转录里出现 16 种写法：`Grok` 被听成 `Clock` / `Glock` / `Gokul`，
`Codex` 写成 `CodeX` / `codex`。同一段音频转两遍结果还不一样——第二遍才出现
`Gokul`。所以词典是每次转录都要过的一道闸，不是「偶尔修个别名字」。

## 自己拼播放顺序，误否过两条正确判断（2026-07-26）

判断「说了两遍」靠的是播出来相邻。剪过的项目段号必然跳号，从 `transcript.json`
自己拼视图时，跳号被读成「有内容没给我看」，于是拒绝判断——当天因此误否两条
正确的删词。这就是「必须用 `transcript playback`、不许自己拼」的来历。

## 增量提交把账本退了回去（2026-07-26）

`cuts set` 是替换语义：产品用「停顿基线 ∪ 本次提交」重建删词集合。当天只交了
新找到的词，删词数从 430 掉到 394——声音听着仍对、`changed: true` 一切正常，
但上一轮的语义删词被静默丢掉。这就是「候选必须是本轮完整结论」和「提交后必看
`noLongerCut`」两条的来历。

## 修字为什么必须在删词判断之前

稿子还是错的时候去判断，判断就得一路绕开错名字——判据里那条「专名听错不算
删除理由」本质是补丁。先修字，补丁才不用生效。
