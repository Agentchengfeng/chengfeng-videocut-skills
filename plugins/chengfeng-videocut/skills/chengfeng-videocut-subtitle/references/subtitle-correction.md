# 字幕校对规则

```text
逐词稿 + 账本（都已经存在）
      |
      v
transcript dictionary      固定写法，直接改
transcript align --script  上下文对得上才改，对不上报出来
      |
      v
subtitle build             分屏
      |
      v
Studio 字幕标签页          人逐屏看、改字、调分屏
      |
      v
subtitles.json
```

## 时间

- **字幕不决定时间。** 一屏存的是词 id，不存秒数；时间每次从账本现算。
- **逐词稿要用，原片字幕不能拼。** 这两件事容易混：
  - 拿原片的**字幕条**按账本首尾相接 → 错。字幕条的边界是按原片的停顿划的，剪过之后
    那些边界不成立了，拼出来看着对，落到画面上越往后偏得越多。
  - 拿**逐词稿**里每个词的时间，一个个映射过账本 → 对。词的边界不受剪辑影响，
    映射是算术，没有近似。
- **不需要重新转录。** 词在源片的第几秒，转录里就有；哪几段留着，账本里就有；
  词落在成片的第几秒，两者一算就出来。再送一遍 ASR 是把同样的话重新听一次，
  花钱花时间，还得把专名重改一遍。

## 改字

- **只纠错，不补话。** 视频里没说的话不能出现在字幕上，哪怕补上更通顺。
- 词典管固定写法（「叉」就是「X」），不看上下文；文稿管逐处推断，上下文对不上就报「不敢定」。
- **词典不看上下文，所以它也会改错**——它会把说话人真说的「Skills」normalize 成「Skill」。
  每次都要看那份改写清单，看到不对就去改词典，不要在别处打补丁。
- **词典里没有、文稿里也没有任何一个写法能确认正确时，不许猜。** 报出来让人补词典——
  补进去下一条视频自动就对了，猜对一次下次还要再猜。
- 名字写错比听错更糟。这是「不敢定」宁可报出来也不猜的全部理由。

## 分屏

- 一屏一行。放不下就拆成两屏，不换行。
- 断在句子边界，不断在词中间。判据见 SKILL.md 第 4 节。
- **一两个字的碎片不是一屏。** 它是上一句的尾巴被误当成了句号，并回去。
- 一屏字太多、时间不够读，命令报 `tooFast`，要处理掉再收工。
- **短屏不报警。** 一个逗号一屏必然会有短屏（说话人说得快），那不是缺陷；
  对正常说话报警，报多了就没人看警告了。

## 失效

- 剪辑改了之后，失效必须**精确到屏**：哪几屏的词被剪掉了、丢了哪几个字。
- **不许出现「字幕可能已过期」这类概括提示。** 用户点不动的东西不要告诉他去点。
- 改转录的字时，引用了那些词的屏在同一步里跟着改写；改不动的报出来，不猜。

## 覆盖已有字幕：唯一要问一句的地方

`subtitle build --replace` 冲掉的是人花时间做的分屏和措辞，**产品自己恢复不了**。
这是这个 skill 里唯一需要征求同意的操作。改几个字不要走它。

## 产出

- 产物是 `subtitles.json`，不是 SRT。产出方式是**烧进画面**，所以字体、描边、位置
  必须精确保留——最终画面由我们自己画。
- 尺寸全部是画面的百分比，不是像素，同一份文档在预览尺寸和成片尺寸下画出来一样。
- **烧进画面归导出，那一步还没做。** 在补上之前字幕只在 Studio 预览里可见，
  报告里必须写清楚。

## 已经作废的写法

下面这些是 2026-07-27 之前的，看到要认出来，不要照着做：

| 作废 | 现在 |
| --- | --- |
| 必须先有 `source_cut.mp4` | 不必导出，也不必重新转录 |
| 走 `transcribe --video source_cut.mp4` | 谁也不走 —— 逐词稿加账本就能算出剪后时间 |
| 产出 SRT，`artifact put --type subtitles` | 产出 `subtitles.json`，`subtitle build` / `subtitle set` |
| 字幕是流程的第四段，产出即交棒 | 字幕是一件事，前提是账本存在；干完就停，不指挥下一步 |
| 保留 ASR 的 cue 当字幕分屏 | 分屏按标点（火山会给），其次按停顿 |
